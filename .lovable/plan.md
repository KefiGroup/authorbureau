

## Why the Sync Failed

The error `duplicate key value violates unique constraint "idx_author_profiles_slug"` means another `author_profiles` row already has the same `author_slug` value that the sync is trying to set for this user.

**How it happens:** Line 246 generates `author_slug` from the pen name (e.g., `pauline-teo`). The upsert uses `onConflict: "user_id"`, so it correctly handles duplicate user IDs — but if a *different* `user_id` row already has `author_slug = "pauline-teo"`, the unique index on `author_slug` rejects the insert.

This is the same identity fragmentation issue: the `save-book` fallback previously created an `author_profiles` entry with a random UUID for this author. That orphaned profile already claimed the slug. Now when the real user syncs, their profile can't use the same slug.

## Fix

**File:** `supabase/functions/sync-author-profile/index.ts`

1. Before upserting, check if another `author_profiles` row (different `user_id`) already holds the target `author_slug`
2. If found, either:
   - Append a numeric suffix to make the slug unique (e.g., `pauline-teo-2`), OR
   - Merge/delete the orphaned profile if it was auto-generated (has `directory_status = 'unlisted'` and no real data)
3. Prefer the merge approach: if the conflicting profile is an orphaned stub (unlisted, generated by `save-book`), reassign its books to the real user and delete the orphan

**Concrete changes:**

- After generating `authorSlug` (line 246), query `author_profiles` for any row with that slug AND `user_id != userId`
- If orphaned (unlisted, no meaningful data): update all `books` with that orphan's `user_id` to point to the real `userId`, then delete the orphan profile
- If legitimate (another real author): append `-2`, `-3` etc. to the slug
- Then proceed with the upsert as normal

This also fixes the broader problem of orphaned profiles blocking real authors.
