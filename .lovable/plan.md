

# Plan — Lock Abby's Recommendation + Fix Page Count Mismatch

Two coordinated fixes to BP-06.

---

## Fix 1 — Abby's recommendation must not mirror the user's price

**Root cause**: The "Abby recommends" banner reads `content.suggested_price_usd` and `content.pricing_recommendation` — the same fields the user edits. So when the author types $1.99, the banner re-reads it and appears to recommend $1.99.

**Edge function** (`supabase/functions/generate-bp06-online-course/index.ts`)
After parsing Abby's JSON, snapshot her original recommendation into two new locked fields **before** writing to `author_nodes`:
```ts
content.abby_recommendation = content.pricing_recommendation;          // "free" | "paid"
content.abby_recommended_price_usd = Number(content.suggested_price_usd) || 0;
```
These fields are written once at generation and never touched again.

**Builder** (`src/components/dashboard/builders/bp06/BP06Builder.tsx`)
Read the recommendation banner from the locked snapshot, with a fallback for older drafts:
```ts
const abbyRec = content.abby_recommendation
  ?? (content.pricing_recommendation === "paid" ? "paid" : "free");
const abbyPrice = Number(content.abby_recommended_price_usd ?? content.suggested_price_usd ?? 0) || 17;
```
Banner line uses `abbyRec` + `abbyPrice` only — never `paidPrice`. `persistPricing` continues to write only to `suggested_price_usd` / `pricing_recommendation` and must **not** touch the snapshot fields.

## Fix 2 — Page count badge says "56 pages" but the PDF is 16

**Root cause**: The "56 pages" badge displays `content.page_count`, which is a string Abby invented in the prompt. The actual PDF generated by `workbook-pdf.ts` is shorter because section count × layout produces ~16 real pages.

**Fix**: Compute the page count from the actual workbook structure instead of trusting Abby's guess.

In `src/lib/workbook-pdf.ts`, export a small helper:
```ts
export function estimateWorkbookPageCount(content): number {
  // Cover (1) + Welcome (1) + TOC (1) + sections (~2 pages each w/ ruled lines)
  // + Action plan (1) + Back cover (1)
  const sections = Array.isArray(content.sections) ? content.sections.length : 0;
  return 1 + 1 + (sections ? 1 : 0) + sections * 2 + 1 + 1;
}
```
This matches the renderer's actual layout (each section forces a new page, plus exercises with 6 ruled lines typically spill onto a second page).

In `BP06Builder.tsx`, the Overview badge uses the computed value instead of `content.page_count`:
```ts
const pageCount = estimateWorkbookPageCount(content);
// badge: `${pageCount} pages`
```

If the user wants the badge to be **exact** rather than estimated, the alternative is to render the PDF once on demand and read `doc.getNumberOfPages()` — heavier and only meaningful after a render. The estimate above is within ±1 page of the actual output and updates automatically if section count changes.
