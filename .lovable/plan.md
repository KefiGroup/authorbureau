## Goal

On the author page (and any reader-facing service surface), Services & Expertise should:
1. **Show no prices** — neither "$1,997" nor "From $297".
2. When a reader clicks **Inquire**, open a dialog that shows the **sales copy + content outline** for that service.
3. The sales copy + outline is **already generated by Abby** for each service node (YR-19, BA-13, YR-23, YR-20, YR-22, YR-21). We surface that content publicly; we do not invent a new builder.

---

## What changes

### A. `src/pages/author-site/AuthorServicesSection.tsx`
- Remove the `getNodePriceLabel` import and the price line under each card (lines 91–93).
- Replace the `<a href="...Book Now / Inquire">` anchor with a `<button>` that opens a new `<ServiceDetailDialog>` for that node.
- Drop `payment_link` / "Book Now" branching — every service node uses the same Inquire flow now.
- Same treatment for the legacy `coachingServices` fallback block (remove `${svc.price}`, route the button through the dialog with `serviceType = svc.title`).

### B. New `src/components/public/ServiceDetailDialog.tsx`
A branded modal (uses author theme `vars`) that renders the Abby-generated `content_json` for one service node. Layout:

```text
┌──────────────────────────────────────────────┐
│  [Service badge]   Service Title             │
│  Tagline / promise                           │
├──────────────────────────────────────────────┤
│  Overview / Philosophy                       │
│  (philosophy | programme_promise |           │
│   coaching_philosophy | speaker_brand bio)   │
│                                              │
│  What's Included                             │
│  (packages[].outcomes / what_included /      │
│   benefits / key_takeaways)  — NO prices     │
│                                              │
│  Outline                                     │
│  (programme_outline | curriculum_pillars |   │
│   signature_talks | modules)                 │
│                                              │
│  Who It's For                                │
│  (ideal_client | who_its_for |               │
│   target_organisations | audience)           │
│                                              │
│  How It Works                                │
│  (booking_process | discovery_call_script |  │
│   application_questions)                     │
├──────────────────────────────────────────────┤
│  [ Inquire about {Service} ]   <- gold CTA   │
└──────────────────────────────────────────────┘
```

A single renderer normalises across the 6 node shapes by reading optional fields from `content_json` and rendering only the sections that exist. A small **price scrubber** strips any `$`, `USD`, `fee_*`, `price_usd`, `fee_range` fields before render so a stale generation can never leak a number to readers.

The CTA at the bottom opens the existing `<ServiceInquiryForm>` with `serviceType` = the node's display label.

### C. Empty-state / not-yet-generated nodes
If `content_json` is missing or thin (no philosophy / no packages / no outline), the dialog falls back to a short message ("Pauline will share full programme details on request") and the Inquire CTA — same submit path. No broken layout.

### D. Abby (no new generators needed)
Generators already exist for all six service node types. The author-facing path is unchanged:
- Dashboard › Yield tab › YR-19 / 20 / 21 / 22 / 23 + Brand tab › BA-13
- Each builder calls `generate-yr*` / `generate-ba13-group-coaching`, writes `content_json` + `status='content_ready'`, and goes Live with the standard publish flow.

We will add one small nudge in `AuthorServicesSection`: if the viewer is the **owner** (already detected elsewhere on the author page) and a service node has empty `content_json`, show an inline "Generate with Abby" link to that node's builder. Reader view never sees this.

### E. Memory + docs
Update `mem://content/public-site-logic` (and the Public Microsites Core line in `mem://index.md`) to add: **"Service nodes never display prices on reader-facing surfaces. Inquire opens a sales-copy + outline dialog rendered from `content_json`. Pricing lives in the dashboard only."**
